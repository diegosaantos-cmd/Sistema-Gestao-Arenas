Testar no Celular

Projeto ArenaPlay (trabalhoprogweb) · Abrir o sistema local no celular pela rede Wi-Fi
Inclui como voltar tudo como estava depois do teste

1. Para que serve

O sistema roda no seu notebook em http://127.0.0.1:8000. Esse endereço só funciona dentro do próprio notebook. Este guia mostra como abrir o mesmo sistema no celular, pela rede Wi-Fi de casa — útil para testar a responsividade (menu, botões, carrosséis) num aparelho de verdade.

Nada disso é permanente. É um ajuste só enquanto você testa: quando fecha o servidor, acaba. A seção 7 mostra como voltar ao normal.

2. Antes de começar (pré-requisitos)

  • Celular e notebook na MESMA rede Wi-Fi. Não funciona com o celular no 4G/5G.
  • Não usar rede de convidados. Redes "guest" normalmente isolam os aparelhos.
  • O roteador não pode ter isolamento de clientes (AP isolation) ligado — se tiver, um aparelho não enxerga o outro e só resolve mexendo no roteador.

3. 1 Descobrir o IP do notebook

No terminal do Windows, rode:

ipconfig

Procure o adaptador Wi-Fi e a linha “Endereço IPv4”. Vai ser algo como 192.168.1.235 — esse é o endereço do seu notebook na rede.

Atenção: esse IP é distribuído pelo roteador (DHCP) e pode mudar quando você reconectar o Wi-Fi. Se um dia parar de funcionar, rode ipconfig de novo.

4. 2 Subir o servidor aberto para a rede

Por padrão, o php artisan serve escuta só em 127.0.0.1 — ou seja, só o próprio notebook consegue acessar. Para o celular enxergar, é preciso escutar em 0.0.0.0 (todas as interfaces de rede).

Pare o servidor atual (Ctrl + C no terminal dele) e suba assim:

php artisan serve --host=0.0.0.0 --port=8000
Isso não altera nenhum arquivo. O --host é só um parâmetro do comando — não fica salvo em lugar nenhum.

5. 3 Liberar o Firewall do Windows

Este é o passo que mais trava. Mesmo com o servidor certo, o celular fica “carregando para sempre” e não abre nada. Isso acontece porque o Windows descarta os pacotes em silêncio (por isso trava em vez de dar erro na hora).

São duas causas, e normalmente as duas juntas:

  • A rede Wi-Fi está marcada como Pública (o Windows bloqueia bem mais nesse perfil).
  • Não existe regra liberando a porta 8000.
Nem sempre aparece o aviso do firewall. Se você subiu o servidor pelo terminal, o Windows pode simplesmente bloquear sem perguntar nada. Então não adianta esperar o pop-up: aplique os comandos abaixo.

Como conferir o que está acontecendo

Num PowerShell (não precisa ser admin só para conferir):

# A rede está como Public ou Private?
Get-NetConnectionProfile | Select-Object Name,InterfaceAlias,NetworkCategory

# Já existe regra liberando a 8000?
Get-NetFirewallRule -Direction Inbound -Enabled True |
  Where-Object { $_.DisplayName -match '8000|laravel|php' } |
  Select-Object DisplayName,Profile,Action

A correção (PowerShell como Administrador)

Precisa ser PowerShell, não o Prompt de Comando (CMD). No CMD dá o erro “'Set-NetConnectionProfile' não é reconhecido como um comando interno ou externo”.
Se você já está num CMD como Administrador, basta digitar powershell e apertar Enter — o prompt vira PS C:\…> e aí os comandos funcionam.

Abra o PowerShell como Administrador (botão direito no menu Iniciar → Terminal (Admin)) e rode:

# 1) Marca a SUA rede de casa como Privada (confiável)
Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Private

# 2) Libera a porta 8000 SOMENTE em redes privadas
New-NetFirewallRule -DisplayName "Laravel artisan serve (8000)" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Private

Troque "Wi-Fi" pelo InterfaceAlias que apareceu no Get-NetConnectionProfile (pode ser Wi-Fi 2, por exemplo). Não precisa reiniciar o servidor depois disso.

Por que liberar só no perfil “Privado”? É a opção mais segura: em casa funciona, mas se você conectar num Wi-Fi público (faculdade, café), a porta continua bloqueada automaticamente — seu servidor não fica exposto.

Alternativas (se preferir não usar PowerShell)

  • Regra de firewall pelo CMD (como Administrador): 
    netsh advfirewall firewall add rule name="Laravel artisan serve (8000)" dir=in action=allow protocol=TCP localport=8000 profile=private
  • Mudar a rede para Privada pela interface (não tem equivalente em CMD):
    Configurações → Rede e Internet → Wi-Fi → (sua rede) → Tipo de perfil de rede → marcar “Rede privada”.

6. 4 Acessar no celular

No navegador do celular, digite o IP do notebook com a porta:

http://192.168.1.235:8000

(troque 192.168.1.235 pelo IP que apareceu no seu ipconfig)

Opcional: ajustar o APP_URL

O .env vem com APP_URL=http://localhost. Para navegar funciona normal (o Laravel usa o endereço da requisição e o CSS/JS usam caminhos relativos). Mas se você notar algum link absoluto apontando para “localhost” (que, no celular, significa o próprio celular), ajuste temporariamente: 

APP_URL=http://192.168.1.235:8000
php artisan config:clear
Só mude se precisar — e lembre de voltar depois (seção 7). O .env não vai para o Git, então isso não aparece no commit.

--host=0.0.0.0		 Não — é só um parâmetro do comando, não altera arquivo nenhum. Ctrl + C e suba normal:

Regra de firewall
(porta 8000)		 Opcional. Pode deixar: só libera em redes privadas, e o servidor só responde enquanto o artisan serve estiver rodando. Se quiser remover (PowerShell Admin):
Remove-NetFirewallRule -DisplayName "Laravel artisan serve (8000)"
Perfil da rede
(Privada)		 Opcional. Deixar a rede de casa como Privada é normal e não tem problema. Se quiser voltar para Pública (PowerShell Admin):
Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Public
Resumo: fechando o servidor, o acesso pela rede acaba na hora. O único item que mexe em arquivo é o APP_URL — e ele é opcional.

8. Problemas comuns

SintomaCausa provávelSolução
O celular não abre nada / “site não pode ser acessado” Servidor escutando só em 127.0.0.1 Suba com php artisan serve --host=0.0.0.0 --port=8000
Fica “carregando” para sempre e não aparece nada (não dá erro na hora) Firewall bloqueando: rede como Pública e/ou sem regra para a porta 8000. O Windows descarta os pacotes em silêncio. Aplicar os 2 comandos da seção 5 (rede → Privada + liberar a porta 8000)
'Set-NetConnectionProfile' não é reconhecido… Os comandos foram colados no CMD (Prompt de Comando) em vez do PowerShell Digite powershell no CMD e aperte Enter (o prompt vira PS C:\…>); aí rode os comandos
Não abre e o firewall já está liberado Celular em outra rede (4G) ou rede de convidados / isolamento de clientes Conectar o celular no mesmo Wi-Fi; evitar rede “guest”
Funcionava e parou do nada O IP do notebook mudou (DHCP) Rodar ipconfig e usar o novo IP
Abre, mas sem estilo (sem CSS) Cache do navegador do celular Recarregar forçado / limpar cache do navegador
Algum link leva para “localhost” e quebra APP_URL apontando para localhost Ajustar o APP_URL para o IP (seção 6) e php artisan config:clear
Segurança: enquanto o servidor estiver com --host=0.0.0.0, qualquer aparelho da sua rede pode abrir o sistema. Em casa é tranquilo, mas evite fazer isso em Wi-Fi público (faculdade, café). Ao fechar o servidor, o acesso encerra.
